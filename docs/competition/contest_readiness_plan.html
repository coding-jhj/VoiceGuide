3. 입상권 목표 수준

최소 통과 수준이 아니라 입상권 수준

심사 포인트그냥 제출입상권 제출
문제 정의 시각장애인을 위한 안내 앱입니다. 보행 중 즉시성이 필요한 위험을 온디바이스 탐지와 짧은 TTS/진동으로 줄이는 시스템입니다.
기술 차별성 YOLO로 장애물을 인식합니다. YOLO 결과를 그대로 말하지 않고, IoU tracking, EMA smoothing, 위험도 정책, 물건 확인, 중복 TTS 억제를 거쳐 안내합니다.
검증 실행 영상 1개. 시나리오별 탐지율, 평균 지연, 오탐 사례, 개선 전후 비교, 실패 사례까지 포함.
공익성 시각장애인에게 도움이 됩니다. 보행 보조의 핵심은 “많이 말하기”가 아니라 “위험한 순간에 짧고 확실히 말하기”라는 설계 철학을 제시.
추천 제출 컨셉: “서버 AI 서비스”가 아니라 “네트워크가 없어도 동작하는 온디바이스 보행 보조 + 보호자/관리자 관제 대시보드”로 잡는 것이 좋습니다. 장애인 보조 서비스에서 네트워크 지연은 치명적이므로, 온디바이스 추론 구조 자체가 강한 장점입니다.

4. Ultralytics 공식 자료에서 가져와야 할 근거

Ultralytics는 모델 자체만 제공하는 것이 아니라 export, benchmark, track, solutions 같은 검증 도구까지 제공합니다. 우리 앱의 실시간 실행은 Android TFLite와 자체 경량 tracker를 유지하고, Ultralytics 기능은 모델 변환과 검증, 발표 자료 제작에 활용하는 방향이 가장 현실적입니다. 이렇게 나누면 앱 속도를 떨어뜨리지 않으면서도 공식 자료를 근거로 기술 완성도를 설명할 수 있습니다.

  • YOLO11 공식 문서: https://docs.ultralytics.com/models/yolo11/
  • Export 공식 문서: https://docs.ultralytics.com/modes/export/
  • Benchmark 공식 문서: https://docs.ultralytics.com/modes/benchmark/
  • Track 공식 문서: https://docs.ultralytics.com/modes/track/
  • Solutions 공식 문서: https://docs.ultralytics.com/solutions/
  • Ultralytics GitHub: https://github.com/ultralytics/ultralytics
주의: Ultralytics 모델/코드는 AGPL-3.0 또는 Enterprise 라이선스 조건을 확인해야 합니다. 공모전 제출물에는 “상용 배포 전 라이선스 검토 필요”를 써두는 편이 안전합니다.

우리 프로젝트에 적용할 공식 문서 기반 선택

Ultralytics 기능우리 프로젝트 적용공모전에서 보여줄 결과
Export tools/export_selected_yolo_tflite.py로 선정 모델을 TFLite asset으로 재생성. 모델 파일이 수동 복사가 아니라 공식 export 절차로 재현 가능함을 증명.
Benchmark PC와 가능하면 Android 실기기에서 export format별 추론 시간을 측정. 평균/P95 지연 시간 표, “음성 안내까지 몇 ms 걸리는지” 그래프.
Track 앱 런타임에는 자체 IoU/EMA tracker 유지. Ultralytics BoT-SORT/ByteTrack은 녹화 영상 분석과 비교 검증에 사용. “공식 tracker를 참고했고, Android에서는 지연을 줄이기 위해 경량 tracker를 구현했다”는 설명.
Solutions Object counting, heatmap, trackzone은 제품 런타임보다 대시보드/발표 검증 자료에 활용. 위험 구간, 반복 출현 물체, 시연 영상 분석 자료.
Predict 설정 현재 Kotlin의 confThreshold, iouThreshold를 시나리오별로 조정. 오탐/미탐 개선 전후 표. 예: 컵/휴대폰/의자/사람/자전거 시나리오.
정리: Ultralytics 기능을 앱에 전부 넣는 것이 목표가 아닙니다. 앱 속도를 지키는 기능은 Android에 두고, 공식 기능은 export와 검증, 발표 근거를 강하게 만드는 데 씁니다.

6-1. Android YOLO 추론: android/app/src/main/java/com/voiceguide/TfliteYoloDetector.kt

class TfliteYoloDetector(context: Context) {
    private var interpreter: Interpreter
    private var gpuDelegate: GpuDelegate? = null
    private val modelBuffer: ByteBuffer
    val modelName: String
    var executionProvider: String = "TFLite-XNNPACK"
        private set
    private val inputSize: Int
    private val outputRows: Int
    private val outputCols: Int
    private val isRawOutput: Boolean
    private val confThreshold = 0.30f
    private val iouThreshold  = 0.45f

    init {
        modelName = listOf("yolo11n_320.tflite", "yolo26n_float32.tflite").firstOrNull { name ->
            try { context.assets.open(name).close(); true }
            catch (_: Exception) { false }
        } ?: throw IllegalStateException("TFLite 모델 파일이 assets에 필요합니다.")

        val modelBytes = context.assets.open(modelName).readBytes()
        modelBuffer = ByteBuffer.allocateDirect(modelBytes.size).order(ByteOrder.nativeOrder())
        modelBuffer.put(modelBytes)
        modelBuffer.rewind()

        interpreter = createInterpreter()
        val inputShape  = interpreter.getInputTensor(0).shape()
        inputSize       = inputShape.getOrNull(1) ?: 320
        val outputShape = interpreter.getOutputTensor(0).shape()
        outputRows = outputShape.getOrNull(1) ?: 300
        outputCols = outputShape.getOrNull(2) ?: 6
        isRawOutput = (outputRows == 84)
    }

    private fun createInterpreter(): Interpreter {
        val compatList = CompatibilityList()
        return try {
            if (compatList.isDelegateSupportedOnThisDevice) {
                val options = GpuDelegate.Options().apply {
                    setPrecisionLossAllowed(false)
                    setInferencePreference(GpuDelegate.Options.INFERENCE_PREFERENCE_SUSTAINED_SPEED)
                }
                gpuDelegate = GpuDelegate(options)
                executionProvider = "TFLite-GPU-FP32"
                modelBuffer.rewind()
                Interpreter(modelBuffer, Interpreter.Options().apply {
                    addDelegate(gpuDelegate)
                })
            } else {
                createXnnpackInterpreter()
            }
        } catch (e: Exception) {
            gpuDelegate?.close()
            gpuDelegate = null
            createXnnpackInterpreter()
        } finally {
            compatList.close()
        }
    }
}

6-2. 위험도/진동 정책: android/app/src/main/java/com/voiceguide/MvpPipeline.kt

private fun computeRisk(det: Detection): Float {
    val distanceM = bboxDistanceM(det)
    val area = det.w * det.h
    val centerWeight = 1f - min(0.6f, abs(det.cx - 0.5f) * 1.2f)
    val distanceWeight = when {
        distanceM <= 0.8f -> 1.0f
        distanceM <= 1.5f -> 0.85f
        distanceM <= 2.5f -> 0.65f
        distanceM <= 4.0f -> 0.35f
        else -> 0.15f
    }
    val classWeight = when {
        det.classKo in VoicePolicy.vehicleKo() -> 1.0f
        det.classKo in VoicePolicy.animalKo() -> 0.85f
        det.classKo in VoicePolicy.criticalKo() -> 0.9f
        det.classKo in VoicePolicy.cautionKo() -> 0.65f
        else -> 0.45f
    }
    val sizeBoost = min(0.25f, area * 1.8f)
    return (centerWeight * distanceWeight * classWeight + sizeBoost).coerceIn(0f, 1f)
}

private fun patternFor(risk: Float, det: Detection?): VibrationPattern {
    if (det != null && det.classKo in VoicePolicy.vehicleKo() && risk >= 0.55f) {
        return VibrationPattern.URGENT
    }
    if (det != null && det.classKo in VoicePolicy.everydayKo()) {
        return VibrationPattern.NONE
    }
    return when {
        risk >= 0.75f -> VibrationPattern.URGENT
        risk >= 0.55f -> VibrationPattern.DOUBLE
        risk >= 0.35f -> VibrationPattern.SHORT
        else -> VibrationPattern.NONE
    }
}

6-3. 서버 수신 API: src/api/routes.py

@router.post("/detect", dependencies=[Depends(_verify_api_key)])
async def detect(payload: dict = Body(...)):
    _t0 = _time.monotonic()
    wifi_ssid = str(payload.get("wifi_ssid", ""))
    device_id = str(payload.get("device_id", ""))
    mode = str(payload.get("mode", "장애물"))
    lat = float(payload.get("lat") or 0.0)
    lng = float(payload.get("lng") or 0.0)
    request_id = str(payload.get("request_id") or "")
    request_id = request_id or f"srv-{int(_t0 * 1000)}"
    event_id = str(payload.get("event_id") or request_id or uuid.uuid4().hex)
    session_id = _normalize_session_id(wifi_ssid, device_id)

    if lat != 0.0 or lng != 0.0:
        db.save_gps(session_id, lat, lng)

    objects = _normalize_objects(payload.get("objects", []))
    tracker = get_tracker(session_id)
    objects, motion_changes = tracker.update(objects)

    sentence = build_sentence(objects, motion_changes, camera_orientation="front")
    alert_mode = get_alert_mode(objects[0]) if objects else "silent"

    response_payload = _with_perf({
        "mode": mode,
        "event_id": event_id,
        "session_id": session_id,
        "sentence": sentence,
        "alert_mode": alert_mode,
        "objects": objects,
        "changes": motion_changes,
        "depth_source": objects[0].get("depth_source", "bbox") if objects else "bbox",
    }, _t0, request_id)

    await _publish_dashboard_event(
        session_id,
        response_payload,
        db.get_last_gps(session_id),
        db.get_gps_track(session_id, limit=100),
    )
    return response_payload

“물건 확인”은 별도 모델을 새로 붙이는 기능이 아닙니다. 사용자가 “이거 뭐야”, “손에 든 거 뭐야”, “바로 앞 뭐야”라고 말하면 현재 카메라 프레임의 YOLO 결과 중 손에 들었거나 바로 앞에 있는 물체를 골라 짧게 답하는 기능입니다.

// src/nlg/sentence.py
def build_held_sentence(objects: list[dict]) -> str:
    if not objects:
        return "손에 든 물건이나 바로 앞에 뭔가 없어 보여요."
    closest = min(objects, key=lambda o: o.get("distance_m", 99.0))
    dist_m = closest.get("distance_m", 99.0)
    name = closest["class_ko"]
    if dist_m < 1.0:
        return f"손에 들고 있는 건 {name}{_i_eyo(name)}."
    if dist_m < 2.0:
        return f"바로 앞에 {name}{_i_ga(name)} 있어요."
    if dist_m < 3.0:
        return f"가까이에 {name}{_i_ga(name)} 있어요."
    return "손에 든 물건이나 바로 앞에 뭔가 없어 보여요."
이번 보강: 서버의 /detect_json도 mode="들고있는것"을 별도 처리하도록 고쳤습니다. 그래서 Android가 어떤 업로드 경로를 쓰더라도 일반 장애물 안내가 아니라 물건 확인 문장으로 답합니다. Android 쪽은 즉시 캡처 모드에서 “확인할게요” 음성을 빼고 화면 상태만 바꾸도록 수정해, 실제 답변 음성이 앞 안내음을 끊어버리는 문제도 줄였습니다. 이후 실기기 로그에서 STT result: "이거 뭐야" → force=true → speak immediate=true → start → done 흐름을 확인했습니다. 첫 안내 직후 “네” 대신 실제 명령을 말해도 명령을 버리지 않고 분석 시작 후 이어서 처리하도록 보강했습니다. 물건 확인/질문은 더 이상 JPEG 파일 캡처 경로를 우선 사용하지 않고, 다음 ImageAnalysis 스트림 프레임을 즉시 처리하도록 바꿔 전처리 지연과 FPS 저하를 줄였습니다. 화면 표시도 장애물이 아니라 물건 확인, 주변 확인, 일반 안내로 구분되게 정리했습니다.

7-1. 선정 모델 export 스크립트: tools/export_selected_yolo_tflite.py

from pathlib import Path
from ultralytics import YOLO


ROOT = Path(__file__).resolve().parents[1]
ASSET_DIR = ROOT / "android" / "app" / "src" / "main" / "assets"


def export_selected_model(model_name: str = "yolo11n.pt", imgsz: int = 320) -> None:
    model = YOLO(model_name)
    out = model.export(
        format="tflite",
        imgsz=imgsz,
        half=False,
        int8=False,
        nms=False,
    )
    out_path = Path(out)
    target = ASSET_DIR / "yolo11n_320.tflite"
    target.write_bytes(out_path.read_bytes())
    print(f"exported {model_name} imgsz={imgsz} -> {target}")


def main() -> None:
    ASSET_DIR.mkdir(parents=True, exist_ok=True)
    export_selected_model()


if __name__ == "__main__":
    main()

7-2. Ultralytics tracker는 앱이 아니라 검증 영상에 사용

공식 track 모드는 BoT-SORT와 ByteTrack을 지원합니다. 다만 Android TFLite 앱 안에 Python tracker를 넣는 방식은 실시간성과 구조에 맞지 않습니다. 대신 시연 영상을 PC에서 분석해 “공식 tracker 기준으로도 같은 물체가 연속 추적된다”는 검증 자료를 만들 수 있습니다. 

from ultralytics import YOLO

model = YOLO("yolo11n.pt")
results = model.track(
    source="data/contest_videos/hallway.mp4",
    tracker="bytetrack.yaml",
    conf=0.30,
    iou=0.45,
    persist=True,
    save=True,
)

for frame in results:
    boxes = frame.boxes
    if boxes is not None and boxes.id is not None:
        print("tracked ids:", boxes.id.cpu().tolist())

9. 제출 전 점검

제출 전에는 기능을 더 늘리는 것보다 현재 기능이 실제 기기에서 안정적으로 동작한다는 증거를 먼저 확보해야 합니다. 아래 항목은 공모전 제출물에 들어갈 코드, 테스트, 시연 자료를 빠짐없이 확인하기 위한 체크리스트입니다.

기술 점검 체크리스트

  1. Android 실기기에서 장애물 안내, 찾기, 물건 확인을 각각 5회 이상 실행하고 실패 사례를 기록.
  2. yolo11n_320.tflite 기준 모델을 공식 export 스크립트로 재생성할 수 있는지 확인.
  3. 반복 안내가 너무 잦은 장면과 명시적 질문에 답해야 하는 장면을 분리해 경고 피로를 점검.
  4. bbox 기반 거리 추정은 “정확한 거리”가 아니라 “위험도 판단용 근사값”으로 표현.
  5. Ultralytics tracker는 앱 런타임이 아니라 검증 영상 분석과 비교 자료에 사용.
  6. 테스트 결과, Android 빌드 결과, 시연 영상, 성능 로그를 제출 자료에 함께 첨부.

10. 발표 스토리

한 문장

VoiceGuide는 시각장애인의 보행 중 위험을 스마트폰/웨어러블 카메라로 즉시 감지하고, 네트워크 없이도 짧은 음성·진동으로 안내하며, 보호자/관리자가 대시보드로 상황을 확인할 수 있는 온디바이스 AI 보행 보조 서비스입니다.

3분 발표 흐름

  1. 문제: 보행 보조는 “많은 정보”보다 “즉시 필요한 위험 정보”가 중요합니다.
  2. 해결: Android에서 YOLO를 직접 실행해 지연을 줄이고, 서버는 기록/관제 역할로 분리했습니다.
  3. 핵심 기술: YOLO 탐지, IoU tracking, EMA smoothing, 위험도 정책, TTS/진동, SSE 대시보드.
  4. 검증: 테스트 코드, 시나리오 영상, latency/FPS 리포트, 실패 사례와 개선 계획.
  5. 확장: TFLite/NCNN 비교, 사용자 맞춤 정책, 보호자 알림, 실외 위험 데이터셋 보강.
발표 톤: 완벽한 자율보행 시스템이 아니라, 시각장애인의 보행 중 위험 인지를 돕는 보조 시스템으로 설명합니다. 현재 한계와 검증 방법을 함께 제시하면 기술 신뢰도가 높아집니다.
