Fine-Tuned Model Issue Analysis

파인튜닝된 온디바이스 모델 적용 시 "문/계단" 오인식·고정 탐지 현상 분석

⚠️ 핵심 문제: TFLite 출력 차원(Shape) 변화 및 Android 후처리 코드 불일치

원인 1. TFLite 출력 텐서 Shape 불일치로 인한 오파싱 치명적

YOLO 모델은 학습된 클래스 개수에 따라 TFLite 파일의 출력 텐서(Output Tensor) 형태가 달라집니다. Android 앱의 탐지부(TfliteYoloDetector.kt) 코드는 특정 차원값(84)을 기준으로 후처리 로직을 분기하므로, 클래스 개수를 변경하여 파인튜닝하면 파싱 오류가 발생합니다.

기존 YOLO11n 모델 (COCO 80 클래스)

출력 Shape: [1, 84, 2100]

  • 84개 행 = 4개 좌표 + 80개 클래스 확률
  • outputRows == 84 조건 충족
  • postProcessRaw()로 정상 파싱

신규 파인튜닝 모델 (문, 계단 2 클래스)

출력 Shape: [1, 6, 2100]

  • 6개 행 = 4개 좌표 + 2개 클래스 확률
  • outputRows == 84가 아님 (6으로 바뀜)
  • postProcessEndToEnd()(NMS 파서)로 잘못 오인하여 실행됨

결과 현상:

NMS 파서가 2100개 채널 데이터를 무작위로 분석하면서 비정상적인 플로트(Float) 값을 클래스 ID 정수형(Int)으로 강제 변환합니다. 변환된 값이 COCO_KO 맵에서 특정 클래스(예: 0="사람", 1="자전거" 등)와 매핑되거나 오인식을 유발하여 모든 탐지가 문이나 계단으로 고정됩니다.

원인 2. 클래스 인덱스 매핑(Class ID Mapping) 불일치

YOLO 학습 데이터셋의 .yaml 설정 파일에 정의된 클래스 인덱스 순서와 Android 클라이언트의 한글 매핑 맵(COCO_KO)이 동기화되지 않았을 때 발생합니다. 

// 1. 파인튜닝 학습 YAML 파일 (data.yaml)
names:
  0: door    (문)
  1: stairs  (계단)

// 2. Android 클라이언트 상수 정의 (VoiceGuideConstants.kt)
val COCO_KO = mapOf(
  0 to "사람",
  1 to "자전거",
  2 to "자동차",
  // ...
)

위 예시와 같이 매핑 정보가 어긋나 있는 경우, 모델이 0번("문")과 1번("계단")으로 탐지한 객체를 앱 단에서 잘못 변환하거나 인덱스가 꼬여 고정된 결과만 노출하게 됩니다.

원인 3. 모델 과적합(Overfitting) 및 기존 지식 망각

특정 실내 환경에서 수집한 '문'과 '계단' 데이터로만 지나치게 가파르게 학습(과적합)했거나, 학습 과정에서 기존의 COCO 백본 레이어 지식을 유지하지 못해 발생하는 현상입니다.

  • 망각 현상 (Catastrophic Forgetting): 문/계단 탐지 능력을 키우는 도중 기존의 '사람', '장애물' 등을 식별하는 특징 추출 능력을 완전히 잃어버리는 현상입니다.
  • 형태적 일반화 실패 (Overfitting): 모델이 격자 무늬나 사선 무늬를 모두 '계단'으로, 사각형 프레임 형태의 모든 물체(벽면, 책장, 문틀)를 '문'으로만 인식하도록 편향되어 학습된 경우입니다.

해결 가이드라인 (Troubleshooting Guide)

위 문제를 해결하고 새로운 파인튜닝 모델을 정상 연동하기 위한 순서입니다.

Step 1. TFLite 출력 차원 감지 로직 수정

[TfliteYoloDetector.kt](file:///c:/est/project/VoiceGuide/android/app/src/main/java/com/voiceguide/TfliteYoloDetector.kt)에서 클래스 2개짜리 raw 모델(`outputRows == 6`)도 raw 후처리를 타도록 분기문을 보완합니다. 

// 수정 전
isRawOutput = (outputRows == 84)

// 수정 후 (클래스 N개에 따른 유연한 처리)
isRawOutput = (outputRows == 84 || outputRows == 6)

Step 2. Android 내 클래스 이름 매핑 동기화

[VoiceGuideConstants.kt](file:///c:/est/project/VoiceGuide/android/app/src/main/java/com/voiceguide/VoiceGuideConstants.kt)의 COCO_KO 맵을 파인튜닝 시 사용했던 YAML 파일의 순서에 맞춰 재정의합니다.

Step 3. 파인튜닝 시 백본 레이어 동결 (Freeze)

기존 물체 탐지 지식을 망각하지 않도록 파인튜닝 스크립트 실행 시 freeze=10 또는 freeze=12 옵션을 사용하여 특징을 보존하고 학습률을 기존 대비 낮춰 학습을 진행해야 합니다.
