사업계획서 문장 초안: “향후에는 CCTV·안심 인프라 데이터를 활용해 시각장애인이 위험 지역에 진입했을 때만 일시적으로 관제 상태를 활성화하고, 위험 지역을 벗어나면 모니터링을 종료하는 MLOps 기반 안전 운영 체계를 검토한다.”

강사님께 그대로 물어볼 문장

질문 이유
신청형 Open API를 실제 구현이 아니라 향후 계획으로 두고, 다운로드형 CSV/ZIP/표준데이터를 핵심 구현으로 잡아도 괜찮을까요? 공모전 평가에서 공공데이터 활용을 확실하게 보여주려면 당장 확보 가능한 데이터 중심이 안전하기 때문이다.
장애인콜택시 CSV는 최신 데이터가 아닐 수 있는데, 핵심 안내가 아니라 과거 수요·대기시간 분석 근거로만 써도 될까요? 이 데이터는 “지금 호출 가능”을 말하기 어렵고, 서울 장애인콜택시 이용 패턴을 설명하는 데 더 적합하기 때문이다.
S-DoT 유동인구와 서울 생활인구는 실시간이 아닌데, “혼잡 예측/시간대별 보행 수요 보정”으로 표현하면 괜찮을까요? 실시간 혼잡도라고 말하면 과장이고, 시간대별 위험 보조 근거라고 말하면 더 정직하기 때문이다.
CCTV 데이터는 시각장애인 보행 보조 주제에서 벗어날 수 있는데, 사업계획서의 향후 관제/MLOps 확장으로만 넣는 방향이 괜찮을까요? 치안 앱처럼 보이면 주제가 흐려질 수 있어 표현 범위를 확인해야 한다.
장애인콜택시 API 대신 교통약자 이동지원센터 표준데이터와 서울시설공단 CSV를 쓰는 구성이 더 설득력 있을까요? 직접 안내 데이터와 수요 분석 데이터의 역할을 분리하면 구현 가능성과 시나리오 설득력이 동시에 올라간다.
