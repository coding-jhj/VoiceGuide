공공데이터 활용 방향: 핵심 구현, 보조 분석, 질문 대상 분리

공모전 평가에서 공공데이터 활용 비중이 크기 때문에, 신청이 필요한 Open API나 활용 근거가 약한 데이터는 핵심 구현으로 주장하지 않는다. 바로 확보 가능한 서울/공공데이터를 중심으로 시나리오를 만들고, 애매한 데이터는 강사님께 확인할 질문으로 분리한다.

결론: 핵심 구현은 다운로드 가능한 CSV/ZIP/표준데이터로 구성하고, Open API와 CCTV 관제형 아이디어는 향후 계획 또는 강사님 확인 항목으로 둔다.

서울시설공단 장애인콜시스템 Open API, 서울 실시간 도시데이터 API, CCTV 데이터처럼 신청·권한·개인정보·서비스 범위 문제가 생길 수 있는 항목이다.

강사님께 물어볼 데이터

데이터 왜 애매한가 질문 방향
서울시설공단 장애인콜시스템 Open API 신청이 필요하고, 공모전 기간 내 실시간 연동을 핵심 구현으로 주장하기 어렵다. CSV 분석을 핵심으로 두고 API는 고도화 계획으로 써도 되는지 확인한다.
서울 실시간 도시데이터 API 인증키가 필요하다. 실시간 혼잡도는 좋지만, API 연동 실패 시 기능이 흔들린다. S-DoT/생활인구로 구현하고 실시간 API는 확장으로 둬도 평가상 괜찮은지 확인한다.
CCTV·안심 인프라 데이터 보행 보조와 연결할 수는 있지만, 치안/관제 서비스처럼 보일 위험이 있다. 사업계획서 향후 계획에서 “위험지역 진입 시 관제형 모니터링”으로 표현해도 되는지 확인한다.
팀 설명 문장: “지금 구현은 다운로드 가능한 공공데이터로 확실하게 만들고, 신청형 API와 CCTV 관제형 아이디어는 강사님께 방향을 확인한 뒤 향후 계획으로 넣는다.”
