장애인등록 통계 데이터 VoiceGuide 반영 계획

장애인등록 장애정도별 장애유형별 장애인수(202101~202604) CSV 묶음을 VoiceGuide 프로젝트에 어떻게 활용할지 정리한 적용 계획입니다. 이 데이터는 실시간 위험 감지가 아니라, 서비스 필요성·지역별 수요·대시보드 통계·발표 근거를 강화하는 데 쓰는 것이 가장 적합합니다.

데이터 요약

CSV 파일 수 64개
기간 2021.01~2026.04
전체 행 수 391,583행
인코딩 CP949

컬럼 구조: 통계연월, 통계시도명, 통계시군구명, 장애유형, 장애정도, 등록장애인수. 프로젝트 내부에서는 UTF-8 CSV 또는 JSON으로 변환해서 쓰는 편이 안전합니다.

지도 오버레이는 선택사항

이 데이터는 시군구 통계라 정확한 점 좌표가 없습니다. 지도에 바로 점을 찍기보다는, 행정구역 경계 데이터가 있을 때 choropleth 형태로 붙이는 것이 맞습니다.

전처리 산출물 계획

1. 원본 보관

64개 CP949 CSV를 원본 폴더에 보존합니다.

2. 통합 CSV

월별 파일을 하나의 UTF-8 CSV로 합칩니다.

3. 요약 JSON

최신월, 시각장애, 지역별 집계를 API가 바로 읽게 만듭니다.

4. 트렌드 JSON

월별 시각장애 인구 추이를 차트용으로 저장합니다.

5. 결합 지표

사고다발구역 데이터와 지역 단위로 연결합니다.

datasets/disabled_population/
  raw/
    PDQCSV_22_*.csv
  disabled_population.csv
  disabled_population_summary.json
  disabled_population_trend.json
  visual_disabled_by_region.json

사고다발구역 데이터와 결합하는 방식

바로 직전 반영한 보행자 사고다발구역 데이터는 좌표 기반이고, 이 장애인등록 통계는 행정구역 기반입니다. 둘을 결합할 때는 좌표를 억지로 만들기보다 지역 단위 점수를 만드는 것이 안전합니다. 

region_priority_score =
  normalized_visual_disabled_count * 0.45
  + normalized_hotspot_count * 0.30
  + normalized_hotspot_risk_score * 0.25
  • 시각장애 등록 인구가 많은 지역: 서비스 수요가 큼
  • 사고다발구역이 많은 지역: 보행 위험 노출이 큼
  • 위험점수가 높은 지역: 안전 안내 우선순위가 큼

적용 우선순위

단계 작업 효과 주의점
1차 전처리 스크립트 + 요약 JSON 생성 데이터를 프로젝트 자산으로 안정화 원본은 CP949라 변환 필수
2차 대시보드 통계 패널 추가 서비스 대상 규모를 즉시 보여줌 지도 위 오버레이는 최소화
3차 발표/README 수치 반영 공모전·시연 설득력 강화 기준월을 반드시 함께 표시
4차 사고다발구역과 지역 우선순위 결합 확장 로드맵과 실증 지역 선정 가능 행정구역명 정규화 필요

표현상 주의할 점

  • 이 데이터는 “등록장애인 수”이지 실제 앱 사용자를 의미하지 않습니다.
  • 시각장애 전체를 하나로 묶되, 심한 장애와 심하지 않은 장애를 구분해서 설명해야 합니다.
  • 개인 위치나 개인 장애 정보와 결합하면 안 됩니다. 대시보드에서는 지역 단위 통계로만 사용합니다.
  • 서비스 문구는 “시각장애인의 보행 안전을 보조”로 표현하고, “대체/해결”처럼 과장하지 않습니다.
  • Cloud Run에는 원본 64개 전체보다 전처리 요약 JSON 중심으로 포함하는 편이 배포가 가볍습니다.
