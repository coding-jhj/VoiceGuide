핵심 버그 및 과제 상태

  • "물체 없음" 전송 과부하 방지 조치 완료
    감지 객체가 없을 때 Android 앱이 서버로 지속 전송하던 POST /detect 요청을 로컬에서 가로채 성공 처리함으로써 과부하를 원천 차단했습니다.
  • GPS 시뮬레이션 및 프라이버시 보호 조치 완료
    보안과 시연 편의를 위해 GPS 수집 권한을 제거하고 업로드를 기본 차단(ENABLE_ANDROID_GPS_UPLOAD = false)했습니다. 데모용 이동 동선은 simulator.py를 통해 원격 주입합니다.
  • 방향 안내 및 캘리브레이션 불일치 보완 필요
    Android 앱 측에 5~7시 회피 행동을 추가하고 서버에 동적 캘리브레이션을 연동했으나, 앱 내에서 거리를 보정할 때 클래스명(classKo) 누락으로 항상 기본값(0.12)으로 거리를 도출하는 문제가 잔존합니다.
  • DB 병목 및 서버 빌드 경량화 조치 완료
    PostgreSQL 커넥션 누수 차단 및 불필요한 ML 의존성(torch/ultralytics) 배포본 제외 작업을 완료했습니다.

FastAPI 서버 주요 엔드포인트 구현 현황

메서드/경로 역할 DB 연동 테이블 상태
POST /detect Android 객체 JSON 수집 (주요 업로드 경로) detection_events, detections 활성화

GET /events/{session_id} 실시간 대시보드 이벤트 SSE 스트림 - 활성화

향후 최적화 및 보완 로드맵 (Roadmap)

  • 앱(클라이언트) 측 캘리브레이션 매개변수 연동 보완 우선순위: 매우 높음
    MvpPipeline.kt, SentenceBuilder.kt 내 거리 보정 및 출력 메서드 호출 시 물체의 클래스 이름을 인자로 명시하여, 온디바이스 거리 산정이 정확히 수행되도록 개선합니다.
  • 방향 안내 템플릿 자연어 동기화 우선순위: 보통
    서버의 templates.py 파일 내 5~7시 방향 텍스트 매핑 명칭을 Android 클라이언트 기준("오른쪽 아래", "바로 뒤", "왼쪽 아래")으로 맞추어 일관성을 유지합니다.
  • Android 기기 TFLite 양자화 (FP16/INT8): CPU/GPU 추론 가속화를 통한 FPS 상승 및 기기 발열 완화.
  • Gzip 압축 미들웨어 적용: 대시보드 통신 및 이벤트 전송 시 데이터 크기를 최소화하여 패킷 비용 및 렌더링 지연 감소.
  • Multi-stage Docker 빌드 적용: 프로덕션 Docker 이미지 용량을 최소화하여 배포 리드타임 감축 및 Cloud Run 기동 안정성 극대화.
